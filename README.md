# Heatpump Monitor

A personal learning project inspired by remote maintenance platforms for heat pumps.

The application stores simulated temperature and pressure measurements and displays them in a React dashboard. It is an independent demo with no company affiliation.

## Features

- Device overview with names, locations and demo statuses
- REST API for submitting and retrieving measurements
- PostgreSQL persistence
- Temperature and pressure chart with separate, colour-matched axes
- Chart legend and a dashed pressure line
- Automatic measurement refresh every 10 seconds
- Manual refresh and loading, empty and error states
- Spring Boot Actuator health endpoints

## Technology stack

- Backend: Kotlin, Spring Boot, Gradle, Spring Data JPA
- Database: PostgreSQL 17
- Frontend: React, TypeScript, Vite, Recharts
- Container environment: Docker Compose for frontend, backend and database

## Architecture

The React dashboard communicates with the Kotlin REST API through Nginx in Docker, or through the Vite proxy during local development. The backend reads and writes measurements in PostgreSQL.

The frontend, backend and PostgreSQL database run in separate Docker containers. Nginx serves the dashboard and forwards API requests to the backend.

## Run the full application with Docker

Start Docker Desktop, then run from the project root:

```powershell
docker compose up -d --build
```

The first build downloads dependencies and may take several minutes.

- Dashboard: http://localhost:8082
- Backend API: http://localhost:8081/api/devices
- Backend health: http://localhost:8081/actuator/health
- PostgreSQL host port: 5433

All three services run in Docker. No separate `bootRun` or `npm run dev` process is needed for this mode.

Check service status:

```powershell
docker compose ps
```

Inspect backend logs:

```powershell
docker compose logs --tail=100 backend
```

Stop the application:

```powershell
docker compose stop
```

Database data is stored in a named Docker volume and survives container recreation.

## Run locally on Windows

Clone the repository:

```powershell
git clone https://github.com/mahbejam/heatpump-monitor.git
cd heatpump-monitor
```

### 1. Start the database

From the project root:

```powershell
docker compose up -d database
docker compose ps
```

Wait until the database is healthy.

The local database uses port 5433 on the host. The credentials in this demo are for local development only.

### 2. Start the backend

In a separate PowerShell window, from the project root:

```powershell
cd backend
.\gradlew.bat bootRun --args="--server.port=8081"
```

Keep this window running.

Backend: http://localhost:8081

Health check: http://localhost:8081/actuator/health

### 3. Start the frontend

In another PowerShell window, from the project root:

```powershell
cd frontend
npm ci
npm run dev
```

Keep this window running. Open the URL printed beside `Local`, normally:

http://localhost:5173

Use an additional terminal for other commands.

## Submit a demo measurement

With the backend running, execute this in a free PowerShell window:

```powershell
$sample = @{
    temperatureCelsius = 47.2
    pressureBar = 2.1
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
    -Uri "http://localhost:8081/api/devices/1/measurements" `
    -ContentType "application/json" `
    -Body $sample
```

Select **Heatpump A** in the dashboard. The measurement should appear on the next automatic refresh.

A fresh database contains four demo devices and no measurements.

## API

| Method | Path | Description |
|---|---|---|
| GET | `/api/devices` | List devices |
| GET | `/api/devices/{id}` | Get a device; 404 if unknown |
| POST | `/api/devices/{id}/measurements` | Store temperature and pressure |
| GET | `/api/devices/{id}/measurements` | Get up to 100 latest measurements, newest first |
| GET | `/actuator/health` | Application health |
| GET | `/actuator/health/liveness` | Liveness health |
| GET | `/actuator/health/readiness` | Readiness health |

Measurement timestamps are generated by the backend and returned in UTC. The dashboard displays them in the browser's local time.

## Validation

Temperature and pressure are required and must be finite numbers. Pressure must be non-negative. Unknown devices return 404.

These are basic input checks, not manufacturer-specific operating limits.

## Checks

Frontend type checking and production build:

```powershell
cd frontend
npm run build
```

Run these commands from the project root in separate terminals.

## Current limitations

- Device statuses are seeded demo values.
- Measurements are submitted manually; a continuous simulator is planned.
- No authentication or production security configuration is implemented.
- Backend integration tests currently require the local database.
